Preference-Learning RAG

Iterative retrieval-augmented generation that closes the loop between CRUCIBLE cited reports and PrefNugget contrastive nuggets.

Method

Preference feedback writes the next report.

CRUCIBLE produces a cited report from a request-derived nugget bank. PrefNugget compares two reports, then extracts questions the winner answered more completely than the loser. Those contrastive nuggets are merged into the bank and used to generate a challenger.

Round 0 is the dual pair. Rounds 1+ generate one challenger. The loop stops when research/convergence.py hits the round limit, finds no new nuggets for several rounds, or keeps the same champion. Defaults from experiments/preference_loop.yml: max_rounds: 3, base_nuggets_count: 8, max_contrastive_nuggets: 10.

Framework

Four packages. One orchestrator.

crucible/ and prefnugget/ do not import each other. Only research/ closes the loop.

rag_framework/

Shared substrate

OpenRouter LLM client, RAGTIME Search API, and the document and query models used by every system.

crucible/

Cited reports

Request nuggets, supported-answer extraction, cited report assembly, and citation refinement.

prefnugget/

Preference signal

Pairwise ranking, contrastive nugget extraction, and 0–5 nugget grading.

research/

The closed loop

Preference-learning loop, convergence criteria, and the five-system RAGTIME benchmark.

Supporting directories: experiments/ for YAML configs, examples/ for command-line entry points, and scripts/ for dataset setup and cache warming.

Benchmark

Five systems, one retrieval set.

Evaluation uses TREC RAGTIME (Tier B). Every system receives the same topics and the same retrieved documents.

Query-only coverage

Coverage of generic query-only nuggets, used as an ablation.

Citation coverage

Fraction of report sentences that carry a citation.

Citation validity

Fraction of citations that resolve to a retrieved document ID.

RAGTIME F1 proxy

Harmonic mean of gold coverage and citation validity.

Pairwise win rate

Rate at which the full loop is preferred over each baseline.

Ideas

What the loop is testing.

01

Actionable feedback over scores

Pairwise preference judgments give attribute-specific signal. A scalar score does not tell the next report what it missed.

02

Nuggets that a single pass misses

Preference-discovered nuggets should cover facets a one-shot generator never writes down, raising gold coverage and citation quality relative to one-pass CRUCIBLE and a query-only baseline.

03

The loop those papers leave open

This repository is the closed generation–evaluation loop left as future work by CRUCIBLE (ECIR 2026), PrefNugget / Too Many Questions (SIGIR 2026), and Insider Knowledge (ECIR 2026).

Still open

The current evaluation used a small topic set and the same LLM for generation and judging. Gold coverage is a shared ceiling across pipelines. Extra rounds grow report length. Smarter stopping is still unfinished. The larger question remains: judge-aligned improvement is not yet gold-aligned improvement.
